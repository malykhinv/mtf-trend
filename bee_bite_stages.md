# Bee Bite Stage Contract

Этот файл фиксирует текущую договоренность по стадиям стратегии `bee_bite`.

## Stage 1

Задача: оставить только активы "в игре".

Stage-1 включает только:

1. Спячку
2. Памп
3. Проверку, что после пампа цена не скатилась ниже `0.5` его высоты

Что считается валидным для stage-1:

- `24h` объем не ниже `20M USDT`
- до пампа есть спячка длиной `7 дней`
- в спячке нет резких пампов или дампов
- после спячки есть памп на `15m` величиной `15%+`
- средний объем после начала пампа как минимум в `15x` выше среднего объема спячки
- после пампа цена не уходит ниже `0.5` высоты пампа

Что stage-1 не делает:

- не определяет боковик
- не определяет confirmed high
- не различает sweep и новый импульс
- не ищет точку входа

Итог stage-1:

- актив либо проходит грубый структурный фильтр
- либо отбрасывается

## Stage 2

Задача: определить структуру удержания после пампа.

Stage-2 включает:

1. Определение confirmed high пампа
2. Определение верхнего боковика
3. Разбор последовательности перехаев внутри удержания

Рабочая модель:

- мы храним все confirmed high пампа
- каждый участок между соседними confirmed high считаем отдельной проторговкой
- если две соседние проторговки перекрываются по ценовому диапазону на `50%+`, считаем их одной проторговкой
- промежуточный confirmed high внутри такой объединенной структуры считается верхней границей локального участка
- верхняя граница объединенного боковика определяется максимальным confirmed high внутри объединенной структуры

Отношение к теням:

- одиночная тень выше confirmed high сама по себе не образует новый confirmed high
- тень без подтверждения считается sweep
- новый confirmed high появляется только при реальном новом импульсе по правилам stage-2

Итог stage-2:

- найден верхний боковик
- определены его верхняя и нижняя границы
- определено начало боковика

## Stage 3

Задача: дождаться выноса ниже нижней границы боковика.

Stage-3 включает только событие:

- цена выносит вниз нижнюю границу боковика, найденного на stage-2

Stage-3 не делает:

- не открывает позицию
- не подтверждает вход
- не управляет риском

Итог stage-3:

- зафиксирован факт выноса вниз

## Stage 4

Задача: работа с позицией.

Stage-4 включает:

- поиск точки входа после stage-3
- подтверждение входа
- постановку stop-loss
- сопровождение позиции
- выходы и управление сделкой

## Архитектурная граница

Чтобы не смешивать стадии:

- `stage-1` отвечает только на вопрос: "монета ожила после спячки и не умерла сразу?"
- `stage-2` отвечает только на вопрос: "где боковик и какие у него границы?"
- `stage-3` отвечает только на вопрос: "боковик уже вынесли вниз?"
- `stage-4` отвечает только на вопрос: "как и где торговать позицию?"
