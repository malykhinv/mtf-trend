# Проторговка после отката

## 1. Технологии и базовые правила
- Язык: Python. 
- Строгая типизация. 
- Использовать только `@dataclass`, `Enum`, `TypedDict` для хранения данных (TypedDict — только на границе парсинга внешних JSON).
- CCXT, одна биржа за запуск (`config.EXCHANGE`).
- Таймзона всех времён: `Europe/Belgrade`. Указывается в конфиге.
- Маржа: `isolated`. Режим: `single` (без хеджирования).
- Комиссии/проскальзывание: **не учитывать** в любых расчётах (лайв и бэктест).
- Вся конфигурация — в `config/config.py`. Ключи — в `.env`. 
- Никакой рефлексии (`hasattr/getattr/isinstance/try import`). В домене — никаких словарей.
- Логи: русский, формат `ЧЧ:ММ:СС Сообщение`. Отдельная утилита логирования.
- Баланс и маржа: USDT.

## 2. Получение данных (REST)
- Всегда REST, WebSocket **не использовать**.
- Последовательность: получить список фьючерсных символов → отфильтровать → для каждого символа выполнять REST‑проход по TF.
- При активации слежения по символу — продолжать REST только для него;

## 3. Первичная фильтрация символов
- Для каждого фьючерса определить «возраст листинга».
  - Листинг ≤ 14 дней: `volume_usdt_24р > 5_000_000`.
  - Листинг > 14 дней: одновременно `volume_usdt_24р > 50_000_000`, `trades_24h > min(1_000_000, 0.5 * btc_trades_24h)` и `has_high_volume`.
- `volume_usdt_24р` — объем за 24 часа. 
- `trades_24h` — количество сделок за 24 часа по символу. 
- `btc_trades_24h` — количество сделок за 24 часа по биткоину.
- `has_high_volume` - True, если на символе присутствуют повышенные объемы.
